# Kinds

One file per kind (or per pair of kinds built together), named after the
kind: what gap it fills, where its code comes from, its notes, and its
live runs. A kind's pull request adds or edits its own file and no shared
list, so sibling pull requests do not conflict here.

`task kinds` prints every kind as a table (`hack/kinddocs`); the table
is not committed. `task check:static` fails if a CRD in `config/crds/`
has no file here, or a file names a kind without a CRD.

A file starts with front matter, then the sections below:

```markdown
---
kinds: [LoggingSavedQuery]
apiVersion: logging.gcp.hfl.dev/v1alpha1
---
# LoggingSavedQuery

`logging.gcp.hfl.dev/v1alpha1`

**Gap it fills.** One line: what it manages and why Config Connector's
kinds do not.

**Source.** Where the code comes from (copied from upstream's ..., or
generated by `hack/discokind`).

## Notes

What was built, what live taught, what is left for this kind.

## Live runs

| Date | Commit | Mock | Live | Differences seen | Cost-relevant resources made and deleted |
| --- | --- | --- | --- | --- | --- |
```

`hack/discokind` writes this file for a generated kind when it is
missing. Runs before 2026-11-11 are in `docs/live-runs.md`'s ledger, and
notes from before then in `docs/design.md` sections 6 and 7; those stay
where they are.
