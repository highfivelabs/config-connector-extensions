# IAMWorkforcePoolProviderScimToken

`iam.gcp.hfl.dev/v1alpha1`

**Gap it fills.** a token for a workforce pool provider's SCIM tenant, which the identity provider presents when it pushes users and groups (Terraform's `google_iam_workforce_pool_provider_scim_token`); in no Config Connector code or pull request (searched 2026-11-23); `docs/coverage/foundation.md` item 4, which called it `IAMWorkforcePoolProviderScimTenantToken` before Terraform had the resource (decision 18 names it after Terraform's).

**Source.** generated by `hack/discokind` from the IAM API's Discovery document

## Notes

The API returns the token (`securityToken`) only in the create's answer,
never on a read. It never goes to status: the controller writes it to a
Kubernetes Secret in the object's namespace, owned by the object, named by
`spec.secretOutput.name` (default the object's name), under the key
`securityToken` (`docs/design.md` decision 38, the `hack/discokind`
options `secretOutputs` and `createOnlyOutputs`). The Secret is made,
empty, before the create, so a Secret of that name that the object does not
own stops the create before a token is made.

**If the Secret is lost, the token cannot be written again.** The object
is then not Ready, and its message says so: delete the object (which
deletes the token in the cloud; it is kept 30 days as `DELETED`) and make
it again, under a new `resourceID` while the old ID is held. An object
that acquires an existing token (one it did not make) is not Ready for the
same reason. The Secret goes with the object, also when it is abandoned.

`workforcePool`, `provider` and `scimTenant` are IDs. The API serves
tokens for Gemini Enterprise only.
